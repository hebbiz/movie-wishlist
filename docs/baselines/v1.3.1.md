## Validation evidence

### Verified from the repository

- `v1.3.0..a59b900` contains 13 commits and changes only `app.js`,
  `styles.css`, migration 015 and migration 016.
- The diff implements the rating-control refinements, cross-group add/copy,
  owner-only group rename and mobile group-edit stabilization recorded in the
  changelog.
- At preparation time `main` and `develop` had identical trees.
- The repository contains no root README/CHANGELOG before this preparation, no
  package scripts, no automated test files, no GitHub workflow and no
  `netlify.toml`.

### Owner-confirmed evidence

- The owner states that the latest changes are published to Production and have
  been validated through real use.
- The owner previously confirmed the group-copy cases and group rename/mobile
  editing behavior in the live application.

These statements are accepted as release evidence, but they are not presented
as tests independently performed during baseline preparation.

### Not independently verified

- the exact commit currently deployed by Netlify;
- the Supabase migration ledger and whether each repository migration was
  applied to every environment;
- deployed Edge Function versions, database webhooks, Vault values and cron
  configuration;
- a fresh end-to-end production smoke test.

## Known limitations and technical debt

- No automated test suite or required CI check is defined in the repository.
- No canonical local start/build command or lockfile is present.
- Live Netlify and Supabase configuration is external to the repository.
- The v1.3 `database.sql` file remains a historical v1.3.0 snapshot and does not
  incorporate migrations 015 or 016; this is intentional archival preservation.
- A normal movie-activity push can temporarily set the operating-system app
  badge without the Social Advice unread contribution. The PWA recomputes the
  combined badge after opening or resuming.
- The source `develop` branch was behind `main` in merge history despite an
  identical tree; release completion must synchronize the branches.
- `MW-FUT-01` and `MW-FUT-02` have no implementation claim in v1.3.1 and remain
  Discovery work.

## Repository state versus deployment state

The Git baseline identifies what is eligible to become v1.3.1. It does not, by
itself, identify what Netlify or Supabase currently executes. The owner-confirmed
production result supports release preparation, while the deployed commit and
migration state remain independently unverified. Final release completion must
record the actual main commit, create tag `v1.3.1`, publish the GitHub Release
and synchronize `develop` with `main`.
